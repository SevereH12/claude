# Storm Bottler: whole-game review (October 2026)

Reviewed on branch `claude/sweet-planck-ea1ob4` at commit `c940c53`, after
prompts 1–18 and the researcher parts. No game code was changed.

## Summary

The game is in good shape. Every check passes: `stylua --check`, `selene`
(0 errors, 0 warnings), all 17 harness tests (`test_gameplay Game`: 339
passed, 0 failed), and `tools/check_world.sh Game` (all three worlds:
walkable, flat catch floors, no flicker). Saving is careful (session locks,
retries, receipts confirmed only after a save), every client-to-server
remote is rate-limited and checked, and admin rights are checked on the
server.

The biggest problems:

1. **There is no anti-cheat for movement.** A cheater can teleport onto
   every lightning ring and take all the bolts, mostly in the
   "closest player wins" zones, and fill up the leaderboards.
2. **When a server shuts down (for example after every update), the last
   leaderboard write and the phone reminders can be skipped.**
3. **The economy is short and easy to buy through.** A free player
   reaches the top bottle in about 4–5 hours of good play. One Lightning
   Vault pack (3,999 Robux) is worth about 8 Ascension levels. Ascension
   runs get *shorter* with each level, so the Ascension board ends up
   counting hours played (or Robux spent).

Before you go public you still have to do some setup on the Creator
Dashboard: put the passes and products on sale, set up notifications,
upload the store art, fill in the content questionnaire, and make the game
public. The checklist is below.

## Must fix before launch

### 1. No server check on teleporting or speed hacks (exploit)

- **Where:** `src/server/Systems/Strikes.luau:113` (`distanceInside`) and
  `:98` (`catchingRoot`) decide who catches a bolt using only where the
  character is now. `src/server/Systems/Selling.luau:113` does the same for
  selling. `src/server/Systems/Movement.luau:68` only *sets* WalkSpeed.
  The client controls its own character, so a cheater can change their
  speed or teleport, and nothing on the server notices.
- **Why it matters:** every strike's position goes to every client 1.5 s
  early (`Strikes.luau:363`, `StrikeWarning`). A cheat script can teleport
  onto each ring. In the Single zones (Mesa, Thunderhead Mesa, Ember Mesa)
  the closest player gets the whole bolt, so real players get nothing. Ball
  lightning (`touchRadius`) can be grabbed the same way. The **Bolts
  caught** and **All-time Volts** leaderboards would fill with cheaters
  in the first few days.
- **Suggested fix:** add a small server system (say `Systems/AntiCheat`)
  that stores each player's root position a few times a second. When a
  player moves further than `speed × time × 1.5 + a few studs`, and the
  server didn't move them (Travel, Ascension, AFK lounge, respawn), mark
  them "suspect" for ~5 seconds. While suspect, `Strikes.resolve`,
  `sellAtStation` and the ball lightning check skip them. Also skip a
  player whose `Humanoid.WalkSpeed` is above what `Movement` set. Log
  repeat offenders for the admin panel, but don't auto-ban (lag looks
  like a teleport too).

### 2. A server shutdown can skip the "player is leaving" step (bug)

- **Where:** `src/server/Systems/PlayerData.luau:474` (`onShutdown`)
  removes every session and saves them, but never fires
  `PlayerData.Leaving`. Two systems rely on that signal:
  `Systems/Leaderboards.luau:272` (writes the player's last scores) and
  `Systems/Notifications.luau:263` (queues the "daily reward ready" and
  "streak ends soon" reminders).
- **Why it matters:** when a server closes (every Update + "Restart
  servers", or Roblox closing a server), `BindToClose` can run before
  `PlayerRemoving`. Then `onPlayerRemoving` finds no session and returns
  early. Up to 5 minutes of leaderboard progress is lost, and nobody in
  that server gets a reminder. The reminders are the point of the
  notification feature.
- **Suggested fix:** in `onShutdown`, fire
  `PlayerData.Leaving:Fire(player, session.profile)` for each session
  before `release` (in the same `task.spawn`). Keep the 25-second wait so
  the leaderboard writes have time to finish.

## Should fix (soon after launch is fine)

1. **Playtime gifts restart every visit** (`Systems/Rewards.luau:108`,
   `startedAt` is set per session at `:148`). Leave and rejoin every hour
   and you get all six gifts again: 640 bolts plus two 10-minute boosts an
   hour, about **+26% income** at Ember Mesa. AFK players who are moved to
   a fresh server also start a new set. Fix: count playtime per UTC day
   (save it in the profile), or only reset the gifts after 4+ hours away.

2. **AFK players make the server goal bigger but can't help fill it**
   (`Systems/ServerGoal.luau:76-86` adds every present player's grinding
   rate; the AFK Lounge doesn't count toward filling it). A server with
   many overnight AFK players gets a goal nobody can reach. Fix: leave
   out players where `Afk.isAfk(player)` is true when working out the size
   (and call `recompute` when someone starts or stops being AFK).

3. **Invite rewards can be farmed with alt accounts**
   (`Util/Social.luau:63`, `Config.INVITES`: accounts 3+ days old, 5 a
   day). That's up to 2.5 hours of 2x Volts a day for nothing, which cuts
   into 2x Volts pass sales. Fix: only pay the inviter after the new
   player has played 10+ minutes or made their first sale, and raise
   `minAccountAgeDays` to 14–30.

4. **Error reports can be spammed** (`Systems/Errors.luau:84`). A
   cheater can send 5 made-up errors a minute. Each new text becomes a new
   `reported` key (this table never shrinks) and a new Analytics "Error"
   field value. Fix: cap `reported` at about 500 keys per server, and
   stop sending new client fingerprints to Analytics after about 50 per
   server.

5. **One broken system stops the whole server**
   (`src/server/init.server.luau:22-26`). Every system's `init()` runs
   without `pcall`, so one error (for example a DataStore or Http call
   failing at load) stops every system after it, and the order changes
   each time (it loops over a dictionary). Fix: wrap each `init()` in
   `pcall` and `warn` the system's name on failure.

6. **The snapshot is large and sent very often** (`Systems/Sync.luau`).
   Every catch marks the player dirty, and each flush (up to 10 a second)
   rebuilds and sends the whole snapshot: researchers, quests, the whole
   Storm Log view and so on. In a busy storm that's a lot of network and
   CPU, which hurts most on phones. Fix: send the Storm Log and quest views
   only when they change (keep a version number), or cap flushes at about
   4 a second per player.

7. **Researchers keep their posts after Ascension**
   (`Systems/Ascension.luau` `confirm`; `Systems/Research.luau:227`).
   Researchers posted in Ember Mesa and other late zones stay there, but
   the player is back on the Jar, so their perks are off until each one is
   moved by hand. Fix: on Ascension, move researchers in zones the player
   can't enter back to `"Office"` and say so on the confirm screen.

8. **Ascension isn't saved straight away** (`Systems/Ascension.luau`
   `confirm`). Call `PlayerData.saveNow(player)` after it, as Receipts
   does, so a server crash can't undo it.

9. **AFK earnings in the last minute are lost when you leave**
   (`Systems/Afk.luau:359`: the leave handler drops the session without
   `pay`). This is small (under a minute of AFK pay), but easy to fix:
   call `stop(player)` before PlayerData's leave save.

10. **Two Storm Log pages can't be finished without Roblox Premium.**
    `Util/StormLog.luau:77` (`sortedZones`) includes Aurora Reef, which is
    Premium-only, in the Bolts and Places pages. Without Premium your Log
    bonus stops at +4% instead of +8%. Decide whether that's what you want.
    If not, leave Premium zones out of the page totals.

11. **Reminders are queued even for players who said NO**
    (`Systems/Notifications.luau:206`: `notifyAsked` is set when the
    question is shown, not when the player answers yes). Roblox drops them,
    but each one costs a MemoryStore write and an API call. Save the
    answer instead.

12. **The checks don't run on this branch.** `.github/workflows/ci.yml`
    only runs on pushes to `main` and only runs stylua and selene. Add this
    branch, the `tools/harness/test_*.luau` runs and (if possible) a
    `luau-lsp analyze` strict type check. There's no type checker here at
    the moment, and 35 `:: any` casts in `src` (not counting `World/`) hide
    type errors.

13. **README is out of date at the top.** "Features" still lists 4
    bottles and a "server city meter (placeholder)", and "Code layout"
    lists only the first few systems. New players of your *code* (or a
    future you) will be confused. Rewrite those two sections.

## Balance notes

Worked out with the game's own maths (`Util/Afk` grinding rate, which is a
little *higher* than real play), with no passes and the best boots you can
afford at each bottle:

| Bottle | Best zone | Volts / hour | Next bottle + boots | Minutes | Total hours |
| --- | --- | ---: | ---: | ---: | ---: |
| Jar | Shoreline | 5.7K | 380 | 4 | 0.1 |
| Vial | Shoreline | 6.9K | 1.2K | 10 | 0.2 |
| Flask | Mesa | 30K | 3.5K | 7 | 0.3 |
| Battery Pack | Mesa | 35K | 18K | 31 | 0.9 |
| Storm Cell | Generator Yard | 126K | 75K | 36 | 1.5 |
| Tempest Tank | Tidewire | 491K | 350K | 43 | 2.2 |
| Dynamo Drum | Rune Spire | 2.9M | 1.6M | 33 | 2.7 |
| Rune Cell | Cloudshore | 6.9M | 8M | 69 | 3.9 |
| Storm Core | Ember Mesa | 24.5M | 10M (Ascension) | 25 | 4.3 |

**1. The whole game takes about 4–5 hours (maybe 8 in real play).** That
is short for a simulator. With 2x Volts and VIP (×2.2) it's about 2 hours.
On a Double Volts Weekend with a Server Surge running it's under an hour.

**2. How the multipliers stack** (`Util/Passes.luau:148`, they all
multiply):

| Source | × |
| --- | ---: |
| 2x Volts (pass or boost) | 2 |
| VIP | 1.1 |
| Group | 1.1 |
| Server Storm | 2 |
| Server Surge | 2 |
| Double Volts Weekend | 2 |
| Storm Log (4 pages) | 1.08 |
| Friends (3) | 1.15 |
| **All at once** | **24.1** |
| Ascension level 5 / 10 | ×3.5 / ×6 → **84 / 144** |

On top of that, each bolt can be multiplied again. Rare bolts add about
+34% on average (Golden 2% × 10, Rainbow 0.4% × 25, Ball 1% × 5). The
Analyst at rank 6 doubles up to 48% of charges, and Lucky Charges doubles
15%. Together that's about ×2.3 per bolt before the sale multiplier.

**3. The Server Surge is on about half the time.** In an active server the
first goal takes 15 minutes. The Surge's 2x sales fill most of the next
(1.5x bigger) goal, so the next Surge comes about 12 minutes later. That's
roughly three 10-minute Surges an hour. Watch it in Analytics. If it's too
often, make `SERVER_GOAL.growth` 2 or `minutes` 20.

**4. Ascension gets shorter forever.** Cost is `10M × (level + 1)` and the
bonus is `+50% × level`. Both grow in a straight line, so a run takes about
4.3 h, then 3.1 h, 2.0 h at level 4, 1.4 h at level 10, and never more than
about 50 minutes after that. There's no wall and no new reward, so the
**Ascension** leaderboard just counts hours played. Suggestions: make the
cost grow faster (for example `10M × 1.6^level`), or make each level add
less (+50%, +40%, +30%...). Even better, give something to spend on, like
Ascension tokens for a small upgrade shop.

**5. Volts packs can buy Ascension.** A pack pays `charges × your best
zone's bolt value` (`Util/Store.luau:24`). At Ember Mesa (10,000 a bolt):

| Pack | Robux | Volts at Ember |
| --- | ---: | ---: |
| Lightning Vault | 3,999 | 400M (about 16 h of grinding, or about 8 Ascension levels) |
| Thunder Crate | 899 | 60M (about 2–3 Ascension levels) |

Right after an Ascension, though, the same pack is worth almost nothing
(you're back at Shoreline: 5 a bolt). That will feel bad to buyers. Fix
ideas: base the value on the best zone you've *ever* reached, and/or make
Ascension need Volts *earned* this run (not bought). At the least, show
"you'll get X Volts" on the BUY button (it may already show it; check that
it updates after an Ascension).

**6. Rewards at the top end are big.** Day 7 of the login streak is 1,500
bolts: 15M Volts at Ember Mesa, more than the first Ascension costs. Fine
for retention, but remember it when you change Ascension prices.

**7. AFK (10%) is fine.** It can't beat playing, even with every
multiplier.

## Launch checklist for the owner

Do these in order. "Dashboard" means create.roblox.com → **Creations** →
Storm Bottler.

1. **Update and test in Studio.** Click **Update Game**, press Play, and
   check the Output says `[StormBottler] server started` and `client
   started` with no red errors. Walk to Shoreline, catch, sell and buy the
   Vial. Then do a **Team Test with 2 players** (Test tab → Clients and
   Servers → 2 players) to check gifting, friends and the server goal.
2. **Test on a phone and a controller.** In Studio use the Device emulator
   (Test tab → Device) for a phone and a tablet, and play once on a real
   phone after publishing. With a controller, check that the MENU and every
   panel can be used.
3. **Publish** (File → Publish to Roblox) and **save a backup** (File →
   Save to File) before going public.
4. **Turn on settings in Studio:** File → Experience Settings →
   Security: turn on **Allow HTTP Requests** (notifications need it) and
   **Enable Studio Access to API Services** (only for testing saves). Turn
   **Allow Third Party Sales** off.
5. **Put the passes and products on sale.** Dashboard → Monetization →
   **Passes**: open each of the 8 passes, tick **Item for Sale**, check the
   price, save. Then **Developer Products**: put all 4 Volts packs, the 8
   "Gift:" products and the 5 boost products on sale. (The ids are already
   in `Config.luau` and `tools/store/store_ids.json`, but everything was
   made **off sale**.) Fix the balance points above first if you want to
   change pack prices.
6. **Set up phone notifications** (README → "Leaderboards and
   notifications"): make 2 **Notification Strings** (Dashboard →
   Engagement → Notifications), paste their asset ids into
   `Config.NOTIFICATIONS.dailyReadyMessageId` and `streakEndingMessageId`,
   create an Open Cloud API key with **user.user-notification:write**,
   and save it as the secret **`StormBottlerNotifyKey`** (domain
   `apis.roblox.com`). Until then nothing is sent. Roblox also needs 100+
   visits first.
7. **Upload the store art** (README → "Store page art"): `icon.png` as the
   game icon and the 3 `thumb_*.png` pictures as thumbnails (in
   `tools/store/art/`). Roblox doesn't let a script do this, so do it by
   hand.
8. **Write the game page:** a short description (what you do: catch
   lightning, sell, upgrade, 3 worlds), genre **Simulation**, and
   supported devices (Computer, Phone, Tablet, and Console only if step 2
   went well).
9. **Fill in the Experience Questionnaire** (Dashboard → Audience →
   **Maturity & Compliance**). Answer honestly: lightning flashes (there's
   a "reduce flashing" option), no violence, Robux purchases, gifting. You
   can't make the game public without it.
10. **Check who is an admin.** Admins are the owner of the Super Studio
    group and every rank **200 or higher** (`Config.ADMIN_RANK`). On the
    group page, check who has rank 200+ and that you trust them all.
11. **Check the group.** The +10% group bonus and the JOIN button use
    group **7889739 (Super Studio)**. Make sure that's the group that owns
    the game, and that sounds/music uploaded to the group play in the live
    game (open a live server and listen).
12. **Data deletion:** Dashboard → your profile menu → **Webhooks** → add
    one with the **Right To Erasure Request** trigger (a Discord webhook
    works). When a request comes in, run
    `python3 tools/ops/erase_user.py <userId> --dry-run` and then without
    `--dry-run` before the deadline.
13. **Turn on translation** (Dashboard → Localization → **Automatic
    translation**) so players in other languages can read the UI.
14. **Set the server size** (Dashboard → Places → start place → **Server
    fill / Max players**). About 12–16 suits the zone sizes. Private
    servers are already on at 100 Robux a month.
15. **Make it public:** Dashboard → Audience → **Access Settings** → set
    to Public. Then play once on the live game and check the Output (F9
    console) for `[Notifications]`, `[Passes]` and `[Invites]` warnings.
16. **First week:** check Dashboard → **Analytics** every day: the
    Onboarding funnel (where new players stop), `Left` events (where they
    quit), the Economy page, and the custom **Error** event (top errors to
    fix). Fix must-fix items 1 and 2 above before you advertise.

## Fixed after the review

Every "Must fix" and "Should fix" item was fixed (the balance notes and
"Ideas for next" were left alone, as asked). All checks pass: stylua,
selene, all 18 harness tests (`test_gameplay Game`: 339 passed) and
`tools/check_world.sh Game`.

**Must fix**

1. **Movement anti-cheat**: new `Systems/AntiCheat` and `Util/AntiCheat`
   (`Config.ANTI_CHEAT`, tested in `test_anticheat`). Five times a second
   the server compares each player's flat position with where they were
   about a second ago; further than walk speed x time x 1.5 + 6 studs
   makes them "suspect" for 5 seconds, and while suspect `Strikes` (bolts
   and ball lightning) and `Selling` (stations) skip them. Server moves
   (portals, Teleport panel, Ascension's trip home, AFK Lounge, the zone
   lock) and respawns are allowed; Jet Boots and boots count. Nobody is
   kicked; 3+ impossible moves show in the admin panel as `[cheat]`. Not
   done: the "WalkSpeed above what Movement set" check, because a client's
   WalkSpeed change never reaches the server (the server always reads its
   own value); the distance check catches speed hacks instead.
2. **Shutdown skipping the leave step**: `PlayerData`'s BindToClose now
   fires `PlayerData.Leaving` for every session before the final save.
   `Leaderboards` and `Notifications` keep the closing server open until
   their last writes finish (up to 25 s and 10 s).

**Should fix**

1. Playtime gifts count per UTC day across visits (`profile.playtime`,
   `Util/Rewards.playtimeToday`); rejoining carries on, a new day resets.
2. Players in the AFK Lounge for 5+ minutes
   (`Config.SERVER_GOAL.afkExcludeMinutes`) no longer count toward the
   server goal's size; leaving the lounge counts them again.
3. The inviter is paid only after the new player has played 10 minutes
   (`Config.INVITES.playMinutes`) or made a sale (saved in
   `profile.invitedBy`, so it carries over visits); `minAccountAgeDays`
   is now 14.
4. Error reports: at most 500 fingerprints sent to Analytics per server
   (`maxReported`), at most 50 of them from clients (`maxClientReports`).
5. `init.server` loads and inits systems in name order, each in pcall;
   a broken one is reported with its name and the rest still run.
6. Snapshots: at most 4 a second per player (the Storm Log and quest
   view versioning wasn't needed with the cap).
7. Ascension moves researchers in zones the player can't enter back to
   the Office; the confirm screen names them.
8. Ascension saves the profile straight away.
9. AFK earnings since the last payment are paid when the player leaves
   (or the server closes).
10. Storm Log: the Premium zone (Aurora Reef) is a bonus row/entry, not
    needed to finish a page, so everyone can reach +8%.
11. Reminders are only queued for players who tapped YES
    (`profile.notifyYes`); players asked before this change keep them.
12. CI runs on this branch too, plus the harness tests and the map
    checks. Not done: a `luau-lsp analyze` strict type check. It has
    never been run on this code, there's no type checker in this
    environment to clean up its first results, and adding it untested
    would likely turn CI red; the `:: any` casts are still there.
13. README: Features and Code layout rewritten; movement checks and CI
    added.

Profile is now version 18 (`playtime`, `notifyYes`, `invitedBy`), with
a migration and tests.
